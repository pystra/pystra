# PySTRA 2.0.0

PySTRA 2.0 is a new major version of the Python structural reliability library,
and the first since 1.6.0. It rebuilds the public API around one consistent
interface, adds surrogate-assisted, system and decision methods, and makes the
numerics hold up at the very small probabilities that structural reliability
work actually asks for. It is not compatible with 1.x, and it ships with the
tooling to move your scripts across.

```
python -m pip install "pystra==2.0.0"
```

Add the active-learning methods with `python -m pip install "pystra[al]"`.
PySTRA 1.x stays installable with `python -m pip install "pystra<2"`.

## Reliability far into the tails

This is the change we are most pleased with. In 1.x, transforming a Gumbel,
Gamma, Weibull, Fréchet or GEV variable returned an infinite physical value
above about `u = 8.3`, where the standard normal CDF rounds to one: a
reliability index near 8 was already out of reach for those distributions.

In 2.0 every distribution provides `sf`, `isf`, `logcdf`, `logsf` and
`logpdf`, each accurate in its own tail. Transformations evaluate the tail a
point lies in, and switch to log probabilities where ordinary ones underflow,
so they stay accurate to about `|u| = 37.5`, and further for the normal,
lognormal and Gumbel families. That is a failure probability near 1e-300.
SORM, importance sampling and line sampling accumulate in log space and keep a
finite reliability index when the probability underflows, tested to an index of
40.

The numbers check out against independent calculations: with a lognormal
resistance and a Gumbel load, line sampling agrees with direct integration to
four decimals at reliability indices of 4.2, 6.1 and 9.0. The
[high-reliability guide](https://pystra.github.io/pystra/2.0/guides/high_reliability.html)
shows what this covers and where the remaining limits are.

## One consistent interface

- Analyses take `(model, limit_state, *, options=...)`, and `run()` returns an
  immutable result record: `FORMResult`, `SORMResult`, `SimulationResult` and
  the rest, sharing `status`, `n_limit_state_evaluations`, `summary()` and
  `to_dataframe()`. The printing methods and getters are gone.
- Settings are frozen, validated options objects (`FORMOptions`,
  `SORMOptions`, `SimulationOptions`) that reject unknown or unused settings.
  `AnalysisOptions` had nine settings that did nothing; they are removed.
- Simulations take `rng`, a seed or a NumPy `Generator`, instead of the global
  random state, so a seeded run repeats exactly.
- Invalid input raises `ModelError`, and a failed analysis raises
  `AnalysisError`; pass `on_failure="return"` to get the unconverged record
  instead. Nonfinite limit-state values and failing external solvers can no
  longer turn into plausible-looking failure probabilities.
- Names follow PEP 8, acronyms included: `FORM`, `SORM`, `SystemFORM`.
  Extreme-value distributions are named by family — `Gumbel`, `GumbelMin`,
  `Frechet`, `Weibull`, `GEV`, `GEVMin` — and distributions take native
  parameters as keywords, as in `Gumbel("Q", loc=8.9, scale=1.56)`.
- Limit states and analyses no longer store state on each other, so analyses
  that share a model or limit state cannot interfere.

## New methods

- **Active learning:** Kriging with U and EFF learning, adaptive sparse
  bootstrap PCE, sequential PC-Kriging, bootstrap voting, and active
  Gaussian-mixture importance sampling, with independent final sampling,
  convergence diagnostics and UQLab comparisons.
- **System reliability:** `SystemFORM` for series and parallel component
  systems, composition of k-of-n, cut-set and tie-set systems in
  `pystra.systems`, and Ditlevsen bounds.
- **Copulas and joint distributions:** `JointDistribution` with Gaussian,
  Student-t, independent and Frank copulas, Rosenblatt and generalized Nataf
  transformations, and FORM in spherical Student-t space.
- **Strong Maximum Test:** a post-FORM check for competing design points, with
  reproducible sampling and explicit budgets.

## Engineering workflows

Code calibration with normalized reliability, as explicit target-solving,
factor derivation, selection, design and verification operations; assessment
scenarios and load combinations with named cases and roles; design-decision
optimization with the life quality index, societal willingness to pay and
target reliability in `pystra.decision`; and plotting helpers for the usual
reliability figures.

## Faster, with the same evaluations

On the fixed benchmark cases, FORM is 12–37% faster than 1.6.0, SORM 17%
faster, and crude Monte Carlo and importance sampling process more than six
times as many samples per second, with identical limit-state evaluation counts
and matching results. The benchmarks use inexpensive limit states; where an
external solver dominates the cost, the difference is smaller. The method,
machine and raw measurements are in the
[performance evidence](https://github.com/pystra/pystra/blob/v2.0/docs/migration/performance.md).

## Corrections that change results

- Forward finite differences modified the points they were given, so SORM
  computed its gradient transformation at shifted points and its curvatures
  were biased. On the FERUM example the Breitung index moves from 3.85376 to
  3.85387, against 3.85389 from an independent central-difference calculation.
- `GEVMin` (`GEVmin` in 1.x) was wrong in both directions: it took its
  transformation from quantiles of −X, and converted moments with the
  relations for maxima. `GEVMin("X", 10, 3, shape=s)` actually had a mean near
  7.3. Any model using it changes.
- `MaxParent` inverted its CDF by bracketing, which failed for a lognormal
  maximum with large `N`; it now inverts through the maximum's log-CDF.
- A SORM fit whose curvatures leave Breitung's formula undefined now reports
  no estimate and `not_converged`, where 1.x reported 0.0.
- Monte Carlo reports an infinite reliability index when no failures are
  observed, consistent with its zero probability estimate.
- SORM, importance sampling and line sampling no longer reuse a stale FORM
  analysis after the model or limit state changed.
- `Maximum` and `MaxParent` compute their moments by deterministic quadrature
  instead of 100 random draws.

The [changelog](https://pystra.github.io/pystra/2.0/changelog.html) lists every
correction.

## Upgrading from 1.x

Run `python -m pystra.migrate PATH...` on a script or notebook. It makes the
unambiguous changes, shown as a diff, with `--write` to apply them, and reports
what needs your judgment. Then follow the checklist in the
[migration guide](https://pystra.github.io/pystra/2.0/migrating.html), which
links a complete symbol map of every renamed, replaced and removed name. Old
names and module paths raise errors that name their replacement, rather than
failing obscurely.

Converted this way, the 1.6.0 examples and tutorials reproduce their 1.6.0
results, apart from the corrections listed above.

## Requirements

Python 3.12 or later, NumPy 1.26 or later, SciPy 1.11.2 or later, pandas 2.1.1
or later and Matplotlib 3.8 or later; the active-learning methods need
scikit-learn 1.3.1 or later through the `al` extra. Tested on Linux, Windows
and macOS with Python 3.12 to 3.14, on current and on the oldest supported
dependencies: 1,264 tests, all 22 tutorials executed, and the documentation
built with warnings as errors.

## Known limitations

- Transformations are accurate to about `|u| = 37.5` in unbounded tails, and
  further for the normal, lognormal and Gumbel families; the high-reliability
  guide gives the details.
- Simulation convergence histories use 50% more memory than in 1.6.0, for the
  log-probability history that keeps tail estimates finite. Stored samples are
  unchanged.
