# PySTRA 2.0.0 — release note (draft)

> Draft for the GitHub release and the PyPI description. Not yet published.
> Complete the "Before publishing" checklist at the end, then remove it.

PySTRA 2.0 is a new major version of the Python structural reliability library.
It gives every analysis one consistent interface, adds reliability methods and
engineering workflows, and keeps its numerics accurate far into the tails. It is
not compatible with 1.x.

```
python -m pip install "pystra==2.0.0"
```

PySTRA 1.x remains installable with `python -m pip install "pystra<2"`.

## Highlights

- **One consistent interface.** Analyses take `(model, limit_state, *, options=...)`
  and return immutable result records; settings are validated options objects;
  simulations take `rng`; invalid input raises `ModelError` and failed analyses
  raise `AnalysisError`.
- **More methods.** Active learning with Kriging, sparse PCE and PC-Kriging
  surrogates; system reliability; explicit copulas and joint distributions; and
  the Strong Maximum Test, alongside FORM, SORM and the simulation methods.
- **Engineering workflows.** Code calibration with normalized reliability,
  assessment scenarios, load combinations, and design-decision and
  target-reliability studies, with pluggable reliability methods.
- **Accurate at high reliability.** Tail-accurate transformations and log-space
  estimators keep results finite at very large reliability indices.
- **Extension contracts.** `LimitState.evaluate` for points and batches,
  `parameters` and `with_parameters` for distributions, and directed
  transformation Jacobians.

## Upgrading from 1.x

Run `python -m pystra.migrate PATH...` on a script or notebook: it makes the
unambiguous changes (shown as a diff; add `--write` to apply them) and reports
the ones that need your judgment. Then follow the checklist in the migration
guide, which also links the complete symbol map. The 1.6.0 examples and
tutorials, converted this way, reproduce their 1.6.0 results.

Some results change where 2.0 corrects a numerical error, notably SORM
curvatures and every result that uses `GEVmin` (now `GEVMin`). The changelog
lists each correction.

## Requirements

Python 3.12 or later, NumPy 1.26 or later, SciPy 1.11.2 or later, pandas 2.1.1
or later and Matplotlib 3.8 or later. The active-learning methods need the `al`
extra (scikit-learn 1.3.1 or later). Tested on Linux, Windows and macOS with
Python 3.12 to 3.14, and with the oldest supported dependencies.

## Known limitations

- FORM, SORM and importance sampling were up to 39% slower than 1.6.0 on small
  analytic problems, from the tail-accurate transformations and added runtime
  checks; evaluation counts are unchanged. [Replace with the final figures from
  docs/migration/performance.md before publishing.]
- Transformations are accurate to about |u| = 37.5 in unbounded tails, and
  further for the normal, lognormal and Gumbel families; see the
  high-reliability guide for the remaining limits.
