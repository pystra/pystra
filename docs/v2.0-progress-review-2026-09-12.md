**Implementation follow-up — 12 September 2026**

The six prioritized correctness findings have been addressed locally:

- The shared evaluator rejects nonfinite physical points, values and gradients,
  and retains external-solver exceptions as causes. Line sampling propagates
  scan and root-solve failures. Failed simulation reruns invalidate earlier
  successful state. Batched finite-difference and direct-gradient evaluation
  now preserve the point order and return shapes.
- Adding marginals after explicit correlation raises before changing the
  model. Correlation dimensions are checked before replacing dependence.
- SORM, importance sampling and line sampling recompute internally generated
  FORM on each run. Supplied FORM must have converged for the same model,
  expression, settings and coordinates; changed built-in model parameters
  require a rerun. Unknown extension state triggers recomputation. External
  data or state captured by a callable still requires the user to rerun FORM.
- Normal probabilities use stable CDF/quantile operations. `Maximum` and
  `MaxParent` use deterministic quantile integration for moments, with stated
  tolerances; the normal-parent inverse also handles log-tail probabilities.
  These are intentional numerical corrections documented in the migration
  guide and checked against analytic references.
- SORM constructs independent basis seeds for axis-aligned and nearly
  axis-aligned directions, with regressions for both fitting methods.
- Fixed-budget Monte Carlo and importance sampling report `completed` when
  `target_cov=0`, retaining the measured CoV.

Current migration examples now run as doctests, historical examples are
labelled, and the simulation tutorial uses the same model and expression as
its supplied FORM. The migration manifest records the changed contracts.
NumPy's deprecated `fix` call was replaced by `trunc`, and CI's Black command
now honors the project's configured Python targets.

**Highest-priority findings**

1. **P1 — Failed evaluations can become plausible failure probabilities.**
   In [line_sampling.py](../src/pystra/reliability/line_sampling.py), lines
   184–222 catch every exception during scanning, convert it to NaN, treat a
   scan with no valid values as safe, and substitute a bracket midpoint if
   root refinement fails. With a completed FORM supplied and an evaluator
   that always raises `RuntimeError`, two sampled lines returned
   `status="completed"`, `pf=3.6709661993126986e-51`, and CoV `0.0`.
   This can turn a failed FE calculation into apparent high reliability.

   There is a related evaluator-boundary problem in
   [monte_carlo.py](../src/pystra/reliability/monte_carlo.py), lines 116–126:
   all-NaN limit-state values are classified as nonfailures. A 20-sample run
   returned `pf=0.0`, `beta=inf`, and `precision_not_met`; that status describes
   inadequate precision, not invalid evaluations.

   **Recommendation:** reject nonfinite values before classification, retain
   the originating exception and sample/line context, and propagate an
   `AnalysisError` or explicitly invalid result. Require a converged FORM
   prerequisite and a successful root solve. Add external-solver failure,
   all-NaN and partial-invalid-batch regressions; do not silently discard bad
   samples. Audit other methods through the shared evaluator boundary.

2. **P1 — Adding a random variable silently removes existing dependence.**
   [model.py](../src/pystra/model.py), line 76 assigns a new identity matrix
   whenever a marginal is added. This directly contradicts the migration
   plan's instruction to preserve user-supplied correlation.

   Reproduction: standard-normal `R,S`, correlation `0.8`, and
   `g=3+R-S` produce beta `4.74341649025309`. Adding an unused standard-normal
   `Z` resets the matrix to identity and changes beta to `2.121320343559877`.
   The limit-state callable accepted unused keyword arguments for this check.

   **Recommendation:** either reject adding marginals after explicit
   dependence is set, as the explicit-copula route already does, or require
   an explicit enlarged matrix. Check matrix/model dimensions at assignment.
   Also protect the model's exposed mutable name/marginal collections so its
   multiple internal representations cannot diverge.

3. **P1 — SORM can reuse a stale FORM design point.**
   [sorm.py](../src/pystra/reliability/sorm.py), lines 99–113 run FORM only
   while `self.form is None`; internally generated FORM then persists.
   On independent standard normals, run SORM for `3-X-Y`, replace its public
   `limit_state` with `1-X-Y`, and run again. The reused solver reports beta
   `2.1213203435598773`; a fresh solver reports `0.7071067811811925`.

   **Recommendation:** distinguish caller-supplied FORM from internally
   computed FORM, and recompute the latter for each run or validate a prepared
   problem revision. Validate supplied FORM against model, limit state,
   variable order, transformation and conditioning order. Audit importance
   sampling and line sampling, which also cache FORM objects. A frozen result
   snapshot protects old output but does not establish valid reuse of solver
   state. Introduce immutable problem configuration if mutation is intended
   to be unsupported, rather than silently accepting it.

4. **P1 — Tail accuracy and random distribution construction break the suite.**
   `tests/test_distributions.py::TestMaxParent::test_cdf_is_max_cdf_root_n`
   failed while constructing `MaxParent("MP", Normal("N", 0, 1), N=5)`:
   its estimated moments became `mean=-inf`, `std=nan`.
   Independently, `np.random.seed(1)` reproduces the constructor failure.

   [parent.py](../src/pystra/distributions/parent.py), lines 106–109 send
   small representable probabilities to the maximum's PPF. The shared
   [normal PPF](../src/pystra/distributions/distribution.py), line 70 uses
   `erfinv(2*p-1)`, where subtraction loses the small probability. At `1e-20`,
   PySTRA returns `-inf`; SciPy's `ndtri` returns `-9.262340089798409`.
   Meanwhile `MaxParent` and `Maximum` estimate moments from 100 draws using
   NumPy's global RNG during construction. Identical `Maximum` inputs under
   seeds 1 and 2 gave `(mean,std)` of `(1.113699,0.688902)` and
   `(1.080144,0.615360)`. An analysis seed cannot control this earlier variation.

   **Recommendation:** use stable normal CDF/quantile and log-tail operations,
   then replace constructor sampling with deterministic moment evaluation
   with explicit accuracy controls. Test extreme quantiles and compound
   distributions against independent references. Treat any resulting numerical
   changes as deliberate corrections, not rewritten expected values to make
   a test pass. SciPy documents the relevant [ndtri](https://docs.scipy.org/doc/scipy/reference/generated/scipy.special.ndtri.html)
   and inverse-log-CDF route. NumPy's [RNG policy](https://numpy.org/neps/nep-0019-rng-policy.html)
   also supports recording the numerical environment rather than promising
   cross-version reproduction from a seed alone.

5. **P1 — SORM fails on a valid axis-aligned problem.**
   With two independent normal variables, SORM on `3-X` raises
   `ValueError("Singular rotation matrix")`; the equivalent problem `3-Y`
   returns beta approximately 3. The basis assembled in
   [sorm.py](../src/pystra/reliability/sorm.py), lines 572–608 becomes dependent
   for an otherwise valid direction.

   **Recommendation:** construct a numerically robust orthonormal complement
   of the FORM direction, with its orientation made explicit. Add variable
   permutation, unused-variable and nearly axis-aligned regressions for both
   SORM fitting methods. A valid probability problem should not depend on which
   variable is listed last.

6. **P2 — Fixed-budget sampling is reported as a precision failure.**
   `SimulationOptions.target_cov=0` is documented as requesting the whole
   sample budget. But [monte_carlo.py](../src/pystra/reliability/monte_carlo.py),
   lines 339–351 still require `cov <= 0` to report completion. A valid
   1,000-sample run returned `precision_not_met` with a message claiming it
   missed the target CoV of zero.

   **Recommendation:** distinguish budget completion from missing a requested
   precision target; test this for crude Monte Carlo and importance sampling.
   Preserve the measured uncertainty independently of termination status.

**Recommendations for the remaining programme**

- **Make migration examples executable immediately.**
  [migrating.rst](source/migrating.rst), lines 4–8 still describes
  `2.0.0.dev0` and says the result/options changes remain ahead. Its
  "Current example" at lines 266–286 uses removed `stdv` and
  `stochastic_model` keywords; other rows still teach `options.set_imax`.
  Later sections describe the correct new contract, so the same page
  contradicts itself. The warning-free Sphinx build does not exercise these
  literal code blocks. Generate final migration tables from reviewed maps,
  execute every example labelled current, and clearly label historical
  examples. Build the conservative codemod already promised in the plan and
  trial it on representative 1.x scripts.

- **Finish stage 5 through actual studies.**
  Start with one normalized calibration study, one assessment case set and
  one DDO/risk study. Give their consumers a small shared result/evaluator
  interface that retains failed cases, target margins and governing-case
  provenance. `CodeCalibration` currently hard-codes FORM; the decision module
  remains 2,324 lines. Extract shared evaluation/reporting where those examples
  demonstrate reuse, then split decision code by responsibility. Do not make
  a general framework or new inference methods part of the release gate.

- **Complete result consistency without erasing method distinctions.**
  Core results expose `summary`, options and variable names;
  `ActiveLearningResult` still has a separate smaller contract. Supply shared
  reporting adapters or a narrow protocol, plus method identity, effective
  settings and reproducibility metadata. Preserve the active-learning
  distinction between surrogate error, sampling error and stopping criteria.
  Add confidence intervals for ordinary fixed-budget IID Monte Carlo,
  especially zero-failure runs. SciPy provides [exact binomial intervals](https://docs.scipy.org/doc/scipy/reference/generated/scipy.stats.binomtest.html).
  Weighted importance samples, dependent subset samples and adaptively stopped
  samples require their own valid uncertainty treatment.

- **Settle the remaining extension contracts before beta.**
  The plan specifies public row-oriented batches, but public
  `LimitState.evaluate_lsf` still documents and accepts column-oriented points.
  Distribution reconstruction also still relies on `_ctor_kwargs`. Document
  and test the intended public evaluator adapter and distribution
  copy/reparameterization contract while API changes remain possible. Keep
  existing numerical kernels behind adapters; wholesale array conversion is
  unnecessary for this release.

- **Turn the existing verification work into release evidence.**
  CI already measures coverage; the old statement that it is absent is stale.
  Publish a fresh coverage report and inspect failure, tail and mutation
  branches rather than focusing only on the overall percentage. The
  5,061-warning local run is dominated by `np.fix` at
  `_numerics/quadrature.py:58`, now deprecated in NumPy 2.5; the
  [official replacement is `np.trunc`](https://numpy.org/doc/stable/reference/generated/numpy.fix.html).
  Resolve that warning, then review the remaining Gaussian-process convergence
  warnings individually and fail CI on unexpected warnings. Restore a useful
  signal rather than suppressing the whole warning category.

- **Test both dependency boundaries and the current Python release.**
  Keep the agreed Python 3.12 floor while verifying it; add Python 3.14 to the
  core matrix and decide its optional-solver coverage separately. Python 3.14
  was [released on 7 October 2025](https://www.python.org/downloads/release/python-3140/),
  while current CI only tests 3.12/3.13. Establish tested minimum and current
  dependency sets, following the ecosystem guidance in
  [SPEC 0](https://scientific-python.org/specs/spec-0000/) and the
  [SciPy toolchain roadmap](https://docs.scipy.org/doc/scipy/dev/toolchain.html).
  Make CI honor the configured Black targets. Keep FE dependencies in a
  clearly identified optional job, and execute all maintained tutorials before
  RC. Measure transform setup, limit-state evaluation counts, throughput and
  stored-sample memory against a pinned baseline.

- **Complete release automation and public migration access.**
  [publish.yml](../.github/workflows/publish.yml) still permits manual dispatch
  to publish to production PyPI and does not depend on the test workflow.
  Restrict publication to the intended release reference with verified
  artifacts, and adopt PyPI's documented [Trusted Publishing workflow](https://docs.pypi.org/trusted-publishers/using-a-publisher/)
  using a dedicated release environment. Serve stable and development docs
  separately so alpha users can actually follow migration links. Add release
  notes, support dates and attribution, and update the older programme review
  to point to current evidence. Keep the maturity classifier appropriate to
  the release stage; setting Production/Stable during alpha would be premature.

**Suggested delivery order:** first fix invalid-result propagation, model and
FORM reuse, distribution tails/construction, and SORM basis construction.
Repair the current migration examples in the same hardening cycle. Then finish
the bounded stage-5 studies and result adapters, followed by beta migration
trials and the release matrix. Freeze the API at RC only after these gates
pass. The architecture is sufficiently advanced that focused correctness and
adoption work should now dominate the programme.
